# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm start   # static no-cache server on http://localhost:5173 (serve.py)
npm test    # node --test, discovers tests/*.test.js
npm run check  # node --check on every src module, then npm test
```

- Single test file: `node --test tests/scene.test.js`. Single case: `node --test --test-name-pattern "spring"`.
- `npm run check` lists each `src/*.js` file explicitly — **add new modules to that script** or they never get syntax-checked. Nothing checks `scripts/*.mjs`; run `node --check` on one by hand after editing it.
- Browser integration checks: start the server, then `python3 tests/browser_rig.py` (needs Playwright). It drives the real Maker and Viewer — mask pixels, export/import round-trip, gaze, placement validation, cancellation — and writes screenshots to `/private/tmp`. `python3 tests/browser_face_only.py` covers the other rig mode: the dialog's `Blink and talking only` checkbox, the four-region review, dragging an outline point at zoom, and the reduced parameter set that comes out. `python3 tests/browser_record.py` records real takes off the Viewer and probes them (needs `ffmpeg`/`ffprobe` too).
- Open the app through the server, never `file://`; the pages load `src/*.js` as ES modules. `serve.py` exists because plain `python3 -m http.server` sends no `Cache-Control`, so browsers reuse stale modules and a freshly added export appears missing.

## Architecture

Zero runtime dependencies and no build step. The browser loads `src/` directly; Node only runs tests and syntax checks. Two entry points share every module below:

- `index.html` → `src/app.js` — the Maker (layers, keyforms, mesh editing, export).
- `viewer.html` → `src/viewer.js` — the standalone Viewer (load a `.kokoro2d`, procedural performance, mic lip sync).

### Render pipeline

Three stages, each in its own module, composed once per frame:

1. `model.js` `evaluateLayer()` — additively sums every parameter's interpolated keyform (smoothstep between neighbours, relative to the parameter default) onto the layer's base transform and mesh vertices.
2. `scene.js` `evaluateScene()` — walks the parent hierarchy (memoized, throws on cycles) and pushes each layer's vertices through its parent's deformed cage using barycentric weights. Output is world-space vertices with an identity transform, so the renderer never re-applies parent transforms.
3. `renderer.js` `KokoroRenderer.render()` — one WebGL2 program for all layers, sorted by `zIndex`, re-uploading deformed vertices each frame. `clipMask` layers get a stencil pre-pass drawing the mask with `u_mask_pass` (alpha-discard); `maskOnly` layers are never drawn.

`motion.js` `PuppetMotion` supplies the procedural pose for both Maker preview and Viewer. It integrates at a fixed 1/120 s step so springs and blink timing are frame-rate independent, and evaluates `model.physics` **in array order** — a tip spring whose input is a root spring's output must come after it. With no `gaze` it drives itself: `attentionTarget()` holds a glance then saccades, and `weightShift()` eases between stances. `body.bounce` is a driver-only parameter (breathing plus the weight shift's rate of change) that exists for the chest springs to follow, the same way `hair.left` exists for `hair.leftTip`; it is smoothed at a high rate so the transient survives into the spring. The idle is a behaviour model, not a noise generator with a face on it: gaze alternates between the viewer and a deliberate aversion at roughly the conversational 60/40 split, the mouth rests unless a microphone drives it, and the lid follows vertical gaze. When adding to it, prefer things a person does over things a signal does. Two structural choices matter more than any constant in it. Idle drift comes from `pinkDrift()` rather than summed sines, because postural sway is 1/f and periodic idle reads as a loop — a test asserts the autocorrelation stays low. Movement is issued as minimum-jerk submovements through `submove()`, not first-order lag, because a lag is fastest on its first frame and a person is not; a retarget continues from the current velocity and acceleration (`trajectory()`), since restarting from rest made a moving cursor stop the head dead several times a second. Head and body then carry mass: `head.*` and `body.sway` pass through `follow()`, a critically damped second-order filter at the style's `headRate`/`bodyRate` (rad/s), which is what turns a sudden input into a turn rather than a twitch. `headGaze` is the *filtered* gaze share, so the eyes compensate what the head is actually doing — feed the raw aim into the head targets, or the gaze share is lagged twice. The body follows the head by `bodyFollow`, the way a Live2D body angle follows the face angle. Head tilts are a gesture, not noise: when idle attention returns to the viewer she tilts by up to `tiltGesture` with probability `tiltChance`, holds it, and straightens when she looks away or a pointer takes over — a tilt held through an aversion reads as a crick in the neck. Judge changes here by on-screen motion, not parameter values — `body.sway` moves the face further than `head.yaw` does — and by acceleration percentiles over many seeds, since a single seed reshuffles every later random draw. Note that a constant RNG (`random: () => 0.5`) now leaves the character perfectly still, since every pink octave collapses to zero — tests need a real sequence. Its timings are calibrated against published human figures — blink rate and duration, respiratory rate and duty cycle, microsaccade rate — so `tests/motion.test.js` asserts the resulting rates fall inside those ranges rather than matching a number someone liked. Keep that property when editing: a style whose blink rate leaves 10–21/min at rest, or 20–33 in conversation, is wrong regardless of how it looks. Eye and head are coupled, not independent: `eyes.lookX` is the residual `look.x - head.yaw * vorGain`, so the eye counter-rotates as the head arrives and the combined direction holds the target. Anything asserting the eye alone reaches the gaze target is testing the old model. Its constants live in the exported `STYLES` table rather than inline, selected by `new PuppetMotion({ style })` or `setStyle()` at runtime; `calm` is the original performance and `energetic` is the Viewer and Maker default. A style switch deliberately does not reset — pose and springs carry over. When adding a style field, check whether it changes how fast `weightShift()` moves: `bounceDrive` exists because the chest driver is a rate, so a style with faster shifts needs a smaller coefficient or the springs pin at their limit. Every autonomous choice routes through the injected `random`, so seeding it makes the performance reproducible — note that `random: () => 0.5` lands each choice on its midpoint, so she holds still. `speech.js` turns mic RMS + spectral balance into `{open, round, form}`; it is a heuristic, not viseme recognition.

### Model format

`model.js` is the single authority on the `.kokoro2d` schema (`SCHEMA_VERSION = 2`; v1 files still parse, and editing one saves it as v2). Files are self-contained JSON with layer images as data URLs. `validateModel()` enforces the invariants that the rest of the code assumes — keep it in sync when the format changes:

- A keyform's `offsets` length must equal its layer's `mesh.vertices` length. Changing a mesh's resolution invalidates every keyform on that layer.
- `parent.bind` snapshots the parent's **undeformed** cage at bind time (`scene.js` `bindParent()`); hierarchies must be acyclic.
- `clipMask` must point at a different, itself-unmasked layer. Nested masks and blend modes are unsupported.
- Keyform channels may only reference declared `parameters`. `STANDARD_PARAMETERS` is the base set; `layered-rig.js` adds per-strand hair, breathing, chest, mouth-round, and `expr.*` expression parameters. Expressions are deliberately plain 0–1 channels rather than a separate system: they blend additively like every other parameter, so they compose with blink, lip sync and physics instead of overriding them. Adding one means a parameter, keyforms on the layers it should move, and nothing else — the viewer builds its buttons from any parameter whose id starts with `expr.`. Visibility-only overlays (the happy stars) are layers with `transform.opacity = 0` and a keyform adding `opacity: 1`; clip them to the matching eye opening so a blink removes them.
- `meta` carries everything the schema does not validate, so every reader must treat all of it as optional: `meta.regions` (the reviewed placement, kept so a rig can be rebuilt or scored against ground truth), `meta.autoRig` (`{version, faceOnly, confidence, warnings}` — what the Maker's result card renders), `meta.emptyRegions` (hair regions no artwork reached, whose layers and springs were therefore left out), and `meta.motion` (`{style, overrides}`, a performance the file ships with). The Viewer applies `meta.motion` by selecting that named `STYLES` entry and clamping each override to the same range as its matching visible knob in `TUNABLE`: a file may tune the idle, but it cannot push it anywhere a user could not dial by hand.

### Auto-rigger

`✨ Auto-rig PNG` runs entirely in the browser, in three separable stages:

1. `auto-rigger.js` — pure-ish image analysis: background/subject mask → subject bounds → face from skin regions → eye and mouth centres by weighted features. Returns a confidence score and human-readable `warnings`. `prepareAutoRig()` stops here and hands back `defaultRegions()`. Three assumptions here are load-bearing and easy to break again: skin is not background (pale skin is within the flood's colour tolerance of white); a bare neck makes the face and body one region, so `neckRow()` cuts it at the first constriction the body widens out of; and a choker makes them separate regions where the chest is larger, so components are ranked by how high they start (`headliness`) with size only as a square-rooted tiebreak. `static/kokoro-chan-speak.webp` is a useful holdout — it exercises the second case and the first image does not. Confidence must stay a plausibility score — density alone rated a whole-body box at 0.89 — because the placement review is the only thing between a bad estimate and a bad rig, and a user who trusts a high number will skip it.
2. `region-editor.js` `reviewRegions()` — a Promise-based placement review injected into the Maker's dialog. It resolves with edited regions, and **rejects when the dialog closes**, which is how cancellation keeps the current model. It edits outlines rather than boxes (see Region contours below), revalidates on every drag, and holds the build button disabled while an outline is invalid.
3. `layered-rig.js` `buildLayeredRig()` — the actual rig generator. Body geometry it cannot see is derived from the face rectangle (torso width, chest lobe), so there is no `chest` region to place: adding one means extending `validateRegions`' fixed name lists — there are two of them now, since the face-only mode accepts a shorter set — which would then reject `sample.js`' hardcoded regions and every stored `meta.regions`. It does: per-pixel separation into torso/face/bangs/hair canvases, local seam fill (`extendEdges`), skin reconstruction under eyes and mouth, then ~14 layers with parent bindings, stencil-clipped irises, bending lash ribbons, hair spring chains, and all keyforms.

`Blink and talking only` (`#autoRigFaceOnly` → `autoRigFile(file, { faceOnly })` → `buildLayeredRig(…, { faceOnly })`) is that same pipeline with the separation stage skipped. It keeps the masked source as one static `Character` layer instead of cutting the artwork into torso/face/bangs/hair, reviews only `face`/`leftEye`/`rightEye`/`mouth`, and then strips the finished model down to `eyes.blink` and `mouth.open`/`form`/`round` — every other parameter, its keyforms, and all of `model.physics` are deleted *after* the build rather than never generated, which is what keeps the two modes one code path instead of two diverging ones. It exists because a drawing whose hair or body will not separate cleanly can still blink and talk, so treat a change that only works in the full mode as unfinished.

`sample.js` `createLayeredSampleModel()` (the default puppet, and what the Maker loads on `New sample`) feeds the bundled `static/kokoro-chan.webp` through the *same* `buildLayeredRig()` with hand-reviewed regions. Changing `layered-rig.js` therefore changes the default sample and the browser tests. The older `createSampleModel()` + `rig.js` `attachToPortrait()` path builds a single-portrait rig and is retained for the Node tests. A third path refines a portrait that is *already* rigged rather than generating one: `scripts/create-interviewer.mjs` reads `sample.kokoro2d`, swaps the `Character` layer's mesh for a denser grid, re-`bindParent()`s every child onto it, and writes hand-authored head/breathing/posture warps plus an `expr.attentive` channel into `interviewer.kokoro2d` — no re-segmentation and no repainting, so the source artwork survives byte for byte. `tests/interviewer.test.js` guards it by asserting the layer sources are untouched and that no pose flips the sign of any triangle's signed area. A warp that folds the mesh is invisible in a still and glaring in motion, so that second check is worth copying whenever a warp is authored by hand. The script may reauthor the file's *generated* vector layers — the mouth cavity is one — but never its raster layers, which are the cut drawing; the test enforces exactly that line.

Its mouth is the part worth reading before changing anything there, because every mistake it corrects is one a still frame hides. `sample.kokoro2d` predates `layered-rig.js`' collapse-to-the-lip-line code, so the interviewer inherited a cavity that faded in over the lips at a fixed size instead of opening: a skin ellipse rose to full opacity by `mouth.open` .12 and erased the drawn mouth into a flat oval with a visible rim, the cavity itself only reached full opacity at .2 so ordinary speech sat translucent over the lips, and its shape was a scaled copy of itself at every value, so a quiet syllable looked like a shout at lower contrast. The rebuild collapses the cavity onto the lip line column by column and opens from there. Three things about it are load-bearing. Register against the reviewed outline's **lower edge**, not `eyeProfile`'s `closed` chord: the drawn lip line arcs down in the middle, so the chord between the outline's end points runs about 5px above the ink at the centre and meets it at the corners — the inherited `y += 7px` nudge was chasing that, and no single offset can fit it (the rebuilt rest pose sits within 0.41px of the ink, and a test asserts under 1.5). Split the travel unevenly, about 70/30 downward, because a jaw drops and an upper lip barely moves; an even split reads as a hinged beak. And keep the opening concave in `mouth.open` — 22% of full travel at .3 — since `speech.js` saturates early and a linear mouth then spends conversation agape. The cavity texture is regenerated too, as a smooth lens rather than the stretched outline (whose bulging top edge frays into vertical streaks the mesh rows cannot follow) with the tongue kept low and muted: a nearly closed mouth compresses that texture into a few pixels, so whatever it contains is what a quiet syllable looks like, and the stock tongue covered a third of the height and turned every small opening into a pink band. Judge changes here from a zoomed contact sheet across `mouth.open` — at stage-sized zoom the sheet's own downscaling invents streaks that are not in the render — and from frames pulled out of a `previewTalking` recording, which is the only view that shows whether it returns to closed between syllables. One artefact is **not** fixable from this script: a pale flat patch above the lip line is baked into `sample.kokoro2d`'s `Character` raster by the original rig's skin reconstruction, and removing it means repainting the supplied drawing.

#### Landmarks, and the one model call that survived

Before reaching for a landmark model: MediaPipe Face Landmarker was measured here and lost — no detection at all on anime, and 0.36/0.61 mean IoU where it did detect, against 0.65/0.78 for the geometry. Its landmarks trace a human eye opening, not a drawn one, and its face hull excludes the forehead the rig needs. `reviewRegions` answers `autoRigFile` with `{ regions, analysis }` because switching proportions re-estimates the analysis, and `autoRigFile` also accepts a bare regions object. That tolerance is deliberate: when the shape changed, a page holding one old module and one new one produced `undefined` regions and surfaced as "Cannot read properties of undefined (reading 'face')" from inside `validateRegions`, which says nothing about the real cause. Cross-module shapes here should be accepted loosely and rejected loudly. `src/vision.js` is the only thing here that talks to a model, is entirely optional, and asks a local Ollama vision model one question: which `PROPORTIONS` preset the artwork wants. Do not extend it to locating features — that was measured and lost to the geometry, 0.45 mean IoU against 0.61, including a hybrid given a magnified face crop. The prompt asks it to compare eye height to head height on purpose; asked to name an art style it answers "anime" for any illustration. Everything degrades to the manual selector when Ollama is absent, and the review must keep working with `vision.js` unreachable.

#### Proportions

Facial ratios live in the exported `PROPORTIONS` table (`anime`, `realistic`), threaded through `estimateFace`/`estimateFeatures`/`analyzeImageData`/`prepareAutoRig` and switchable live in the placement review, which re-runs the analysis and hands the updated one back through `reviewRegions`. When adding a ratio, add it to both presets — a constant left inline silently applies anime proportions to realistic art. The underlying reason the table exists: a realistically drawn face has much smaller eyes, prominent eyebrows that outscore the lashes on darkness, eye white no brighter than its skin, and a mouth both wider and further below the eyes. Single-ratio heuristics cannot serve both styles — several attempts at multi-scale search, sclera sizing and brow rejection all scored worse and were reverted, and they are recorded here so the next attempt starts further along.

#### Confidence, and measuring a detection change

Confidence is a prediction of accuracy, not a feeling, and it is measurable: generate variants of the bundled drawings whose ground truth transforms with them (flip, scale, pad) or is unchanged (blur, contrast, background), then correlate the reported number against measured IoU. It currently sits at 0.81 Pearson with mean absolute error 0.13, and the property that matters most is that nothing reads confident and wrong — that is what the placement review depends on to earn a skip. `faceSharpness`, `pairAgreement` and the band-centrality term in `densestWindow` exist because the score was blind to blur, to the eyes disagreeing, and to a feature pinned against the edge of its search band. Raising a confidence number honestly means improving the detection or removing a penalty measurement does not support — the no-neck penalty was one, and dropping it improved every calibration figure — never rescaling the output: a least-squares fit of confidence onto measured quality is already near identity, so there is no global bias left to exploit. Peak-to-sidelobe ratio was tried here and lost to absolute response (0.77 against 0.81); the bands are too small for stable sidelobe statistics. Detection changes need measuring, not eyeballing: `sample.js` holds hand-reviewed regions for the bundled artwork, which are the only ground truth in the repo — compare estimates against them by IoU and centre offset, on **both** `static/` renders, since each exercises a different path. `tests/browser_rig.py` asserts mean-IoU floors for both. Score before and after every change and revert anything that does not move the number: weighting the eye score by saturation sounded principled and moved nothing, and sizing features from the weighted spread of their own pixels made things worse, because the spread of a contaminated distribution measures the contamination. One sample is not enough to tune ratios against, so prefer changes justified by a property of anime artwork (mouths are small, eyes sit mid-head, skin is never background) over constants fitted to that one image.

#### Separation, feathering and cropping

Separation boundaries must be feathered (`featherAlpha`) and filled by diffusion (`extendEdges`), or every cut traces a visible contour and every vacated area smears: those two together are most of what makes a rig read as one picture rather than as stacked cut-outs. Feathering only ever reduces alpha, never adds coverage, so a layer cannot grow into its neighbours. Artefacts in a rig are usually easiest to find by exporting each layer on its own and viewing it against a checkerboard — a ghost eyebrow that looked like a classification error turned out to be `extendEdges` streaking, and the eyebrows were not in the layer they appeared to be in. Layers are cropped to their content, so a warp's `u`/`v` span that layer's own rectangle, **not** the source image — map through `imageAt(rect)` before comparing against anything in image coordinates. Getting this wrong is silent: the deformation still runs, it just lands in the wrong place. `contentBounds()` measures each part from its finished canvas (after the seam fill and the restored skin), and a cage layer is the union of the layers it deforms plus a margin, so children are interpolated rather than extrapolated at the edges. `tests/browser_rig.py` asserts every painted layer is mostly opaque and carries a minimum vertex density, which is what catches a regression back to full-canvas textures. Deformation amplitudes in `layered-rig.js` are all relative to the subject or face rectangle, never to the canvas, and never bare constants: the layer covers the whole image but keeps pixels only where its part landed, so a canvas-relative taper puts its travel where there is nothing to move. When judging whether motion reads on screen, measure it — evaluate `evaluateScene()` at a parameter's plus and minus extremes and compare vertex positions, scaled by the renderer's `camera.zoom`. Counting changed pixels or tracking a centroid both mislead: the first is dominated by antialiasing on long edges, and the second cancels out for a local or symmetric lobe.

The jaw sits on a seam. The face is bound to the Head Deformer but the neck is in the Torso, bound to the Portrait Deformer, and the Seam Backing under both copies the original jaw. Any Head Deformer warp that still moves the chin slides the jaw across the neck — the sample's perspective once slid it 4.6px on a turn, which reads in motion as a head wobbling on its stalk. So `authorSampleMotion` fades its yaw/pitch warps to zero between the mouth and the chin and leaves the jaw to the shared cage, and `authorPortraitMotion` pivots `head.roll` at the *base* of the neck so the neck bends into a tilt; pivoting at the chin swung the neck opposite to the crown. Measure a seam by carrying one rest-pose point through each layer that meets there (`triangleWeights` over the layer's rest vertices, applied to the posed ones) and comparing where it lands.

### Region contours (`src/region-geometry.js`)

A region is a rectangle **and** an optional closed outline of 3–64 image-space points. The rectangle stays because crop and mesh sizing still want one, and `setRegionBounds()`/`updateContourBounds()` are what keep the two in agreement — resizing the box scales the outline through it. Contours are optional the whole way down: `sample.js` still hands `buildLayeredRig()` bare rectangles and every consumer falls back to a generated lens or box path, so do not make `contour` required. `addRegionContours()` back-fills one for anything arriving without — from `fitContourToEdges()` when an image is available, otherwise `seedContour()`.

- `fitContourToEdges()` searches only near each seed point, along that point's own outward ray, and keeps the result only if half the points found real contrast and the outline is still valid. It refines a feature already roughly in place; it cannot find a missing eye or tell hair from a lid, and widening its search until it could is how it starts locking onto eyebrows.
- `contourProblem()` returns a sentence the user can act on rather than a boolean — crossed or touching edges, coincident neighbours, a point outside the image, an area flattened to a line. `region-editor.js` runs it on every edit and gates the build button on it, which is why the wording of each message is part of the feature.
- `eyeProfile(r, u)` gives `{upper, lower, closed}` at a horizontal position, tilted eyes included. The eye opening and the lash ribbon must both close onto that same `closed` line, or a blink leaves a gap between them.
- A mouth outline may be flagged `sourceClosed`: the artwork's lips are shut, so the outline traces a lip *line*. `mouthOpeningRegion()` then gives the generated cavity a real height about the same centre, because a closed line describes the drawing and not how far speech can open the mouth. `recoverClosedMouth()` reseeds only when that region is genuinely unusable, so it never moves a placement the user made deliberately.

### Showcase recording (`src/recorder.js`)

The Viewer's `⏺ Record WebM` button hands someone a file instead of a screen share. It does **not** record the stage canvas, and the two reasons are both invisible until you open the result: the renderer clears to transparent, so a direct capture encodes the character onto a black void, and `renderer.resize()` retargets the backing store whenever the window moves, so the video track changes frame size mid-take. `StageRecorder` therefore composites into a canvas of its own — size fixed when recording starts, the stage's own gradient painted underneath, the character fitted rather than stretched so a window resize cannot squash her — and `animate()` pumps exactly one composited frame per rendered frame. `MediaRecorder` gets a timeslice so an interrupted take still holds everything up to the cut, and `stop()` stops only the video track: the audio tracks are borrowed from the microphone that drives lip sync, and stopping those would kill the mouth the moment a recording ended. `tests/browser_record.py` guards all three — the backdrop is asserted by sampling a corner of a decoded frame, not by trusting that it was drawn.

### Maker ↔ Viewer handoff

The two pages share `AUTOSAVE_KEY` from `model.js`: the Maker writes its work there on every change and the Viewer reads it at boot, falling back to the bundled sample. The Viewer also follows `storage` events, but only while it is showing the Maker's puppet — never after a file has been opened.

### Maker state (`src/app.js`)

Single `state` object; `elements` is every `[id]` in the document. Mutations go through `checkpoint()` (push JSON snapshot, cap 80, clear redo) then `changed()` (autosave to `localStorage` key `kokoro2d-maker-autosave-v1`, mark dirty, refresh inspector). Notable rules:

- Dragging a mesh point edits the **base mesh** when the selected parameter sits at its default, and the keyform's **offsets** when a keyform exists at the current value. Neither condition, no drag.
- Parent/clip-mask changes are applied speculatively, run through `validateModel()`, and rolled back on error so an invalid hierarchy never enters history.
- Deleting a layer is refused while another layer parents to it or clips against it.
- Boot recovers the autosave, falling back to the layered sample if it fails to validate.

## Conventions

- Browser-only modules (`app.js`, `viewer.js`, `renderer.js`, `region-editor.js`, and the canvas paths of `auto-rigger.js` / `layered-rig.js`) touch `document`/WebGL only inside functions, never at module scope — that is what lets tests import `auto-rigger.js` and `layered-rig.js` and call their pure helpers under Node. Keep it that way, and use a dynamic `import()` when a Node-testable module needs a browser-only one (see `sample.js`).
- Style is deliberately mixed: the older modules (`model.js`, `renderer.js`, `auto-rigger.js`) are verbose and explicit; the newer ones (`scene.js`, `layered-rig.js`, `region-editor.js`) are dense one-liner-heavy. Match the file you are editing.
- Comments are reserved for non-obvious intent, usually explaining a visual failure the code prevents ("otherwise a blink reveals a second iris"). Write them in that register or not at all.
- The README is written in a deliberately unhinged voice and commit subjects end with `uwu`. Preserve both when editing them.
